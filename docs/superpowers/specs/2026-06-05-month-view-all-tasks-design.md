# 月视图显示全部任务设计

**日期**: 2026-06-05
**状态**: 已确认

## 概述

记录页月视图点击某天后，下方不只显示已有的打卡记录，而是列出该天所有活动任务（startDate ≤ date ≤ endDate），用不同底色区分已打卡和未打卡。

## 交互

- 已打卡任务：正常暖色底，显示 emoji + 任务名 + 打卡描述 + 图片缩略图（可点击预览），长按删除打卡记录
- 未打卡任务：灰底半透明，只显示 emoji + 任务名，长按触发补打（弹出日期选择器，日期预填为选中日期）

## 数据流

`tapDate` 方法中：
1. 从 `_taskMap` 获取所有任务，筛选出该日期范围内的活动任务
2. 从 `_allCheckins` 获取该日期的打卡记录，建立 taskId → checkin 映射
3. 构建合并列表：每个任务 + 其打卡信息（如果有的话）
4. 按"已打卡在前、未打卡在后"排序

## 视觉

| 状态 | 底色 | 显示内容 |
|------|------|---------|
| 已打卡 | 正常 `#FFFBF7` | emoji + 任务名 + 描述 + 图片 + 长按删除 |
| 未打卡 | 灰底 `rgba(0,0,0,0.03)` | emoji + 任务名（灰色文字），长按补打 |

## 长按行为

- 已打卡任务：弹出删除确认 → 删除 checkins 记录 → 刷新
- 未打卡任务：调用补打流程（date 预填为选中日期），直接创建空打卡记录

## 文件变更

| 文件 | 说明 |
|------|------|
| `history.js` | `tapDate` 改为构建全任务视图；新增补打方法 |
| `history.wxml` | 已打卡/未打卡两种 item 样式；长按绑定 |
| `history.wxss` | 未打卡 item 的灰色样式 |

## 边界情况

- 当天无活动任务时显示"当天无任务"
- 任务已删除（_taskMap 中不存在）的任务不显示
- 补打受 targetCount 限制，已达成则 toast 提示
